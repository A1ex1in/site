# Учебная система

Веб-приложение для работы преподавателя и студентов: учебные группы, дисциплины,
курсы, материалы, задания, сдача работ, проверка и электронный журнал.

## Состав проекта

- `backend/` — Node.js, Express, PostgreSQL, серверные сессии и файловое хранилище.
- `frontend/` — статический интерфейс без отдельного этапа сборки.
- `database/` — схема, тестовые данные, проверки и миграции.

Backend сам раздаёт файлы frontend, поэтому для локальной работы достаточно одного
процесса на `http://127.0.0.1:3000`.

## Быстрый запуск

Требуются Node.js 20+ и PostgreSQL 15+.

1. Создайте пустую базу PostgreSQL.
2. Выполните `database/schema.sql`.
3. Для локальной разработки при необходимости выполните `database/seed.sql`.
4. Скопируйте `backend/.env.example` в `backend/.env` и заполните параметры БД.
5. В каталоге `backend` выполните `npm ci`, затем `npm start`.
6. Откройте `http://127.0.0.1:3000`.

Если база была создана до этого обновления, последовательно выполните
`database/migrations/001_backend_completion.sql` и
`database/migrations/002_admin_and_attendance.sql`, затем снова выполните
`database/seed.sql` — он добавляет только отсутствующие тестовые записи.

Тестовые пользователи из `seed.sql`:

- администратор: `admin@example.local` / `Admin123!`;
- преподаватель: `teacher@example.local` / `Teacher123!`;
- студент: `student@example.local` / `Student123!`.

Эти данные нельзя использовать в production.

## Проверки

Из каталога `backend`:

```text
npm test
npm run check
npm audit
```

## Основные возможности API

- `/api/auth` — регистрация, вход, выход, текущий пользователь, профиль и смена пароля;
- `/api/groups` — публичный список активных групп для регистрации;
- `/api/students` — заявки и фильтруемый список студентов для преподавателя;
- `/api/student` — курсы, материалы, задания и работы текущего студента;
- `/api/teacher` — группы, дисциплины, курсы, материалы, задания, работы и журнал;
- `/api/admin` — создание и блокировка пользователей, статистика посещаемости и нагрузки;
- `/api/health` — проверка доступности приложения и PostgreSQL.

Преподаватель отмечает посещаемость внутри списка занятий курса. Администратор
видит сводный процент по группам и нагрузку преподавателей в `admin.html`.

Удаление групп, дисциплин и курсов реализовано как архивирование. Материал нельзя
удалить, пока у него есть файлы; задание нельзя удалить, пока есть файлы, работы
студентов или оценки. Это защищает учебные данные от случайной потери.

## Production

Перед публикацией обязательно:

- задать длинный случайный `SESSION_SECRET`;
- включить HTTPS и `SESSION_COOKIE_SECURE=true`;
- настроить `TRUST_PROXY=true`, если HTTPS завершается на обратном прокси;
- задать точный список `FRONTEND_ORIGINS`;
- хранить `STORAGE_ROOT` на постоянном диске и настроить резервное копирование;
- подготовить утверждённые юридические документы, добавить соответствующие ссылки
  и чекбоксы во frontend, затем включить `REQUIRE_LEGAL_CONSENTS=true`;
- заменить тестовые учётные записи и пароли.

Восстановление пароля по email намеренно не включено: оно требует выбранного
почтового провайдера, домена отправителя и политики срока жизни ссылок. Смена
пароля авторизованным пользователем уже реализована.
